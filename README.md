# Сильна гарантія безпеки винятків у MatrixLib

MatrixLib — статична бібліотека на C++20 для обробки матриць. Проєкт відтворює експеримент із тез: чи залишаються розміри та елементи матриці незмінними, якщо замінити підматрицю не вдалося.

## Що містить проєкт

| Компонент | Призначення |
|---|---|
| `include/matrixlib/Matrix.hpp`, `src/Matrix.cpp` | Клас `Matrix`, перевірки інваріантів, додавання, множення, транспонування, визначник, ранг, обернена матриця та заміна підматриці |
| `examples/` | Програма `MatrixDemo`, яка показує стан матриці до й після невдалої заміни, а також RAII та поширення винятку |
| `tests/MatrixTests.cpp` | 35 тестів GoogleTest у 7 групах |
| `CMakeLists.txt`, `vcpkg.json` | Збирання CMake, реєстрація тестів у CTest і залежність GoogleTest для vcpkg |

## Як зібрати й запустити

Потрібні CMake 3.21+, компілятор із підтримкою C++20 (наприклад, MSVC із компонентом **Desktop development with C++** або GCC) та Git і доступ до мережі, якщо CMake має завантажити GoogleTest. Команди запускаються з кореня репозиторію.

У PowerShell на Windows:

```powershell
cmake -S . -B build -DLAB7_INJECT_BUG=OFF
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
.\build\Debug\MatrixDemo.exe
```

Останній шлях відповідає генератору Visual Studio. Для одноконфігураційного генератора на Windows використовуйте `.\build\MatrixDemo.exe`, на Linux — `./build/MatrixDemo`.

Якщо вже користуєтеся vcpkg, установіть `VCPKG_ROOT` на шлях до його каталогу й виконайте першу команду так:

```powershell
cmake -S . -B build-vcpkg "-DCMAKE_TOOLCHAIN_FILE=$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake" -DVCPKG_TARGET_TRIPLET=x64-windows -DMATRIXLIB_FETCH_GTEST=OFF
cmake --build build-vcpkg --config Debug
ctest --test-dir build-vcpkg -C Debug --output-on-failure
```

Якщо GoogleTest уже встановлено, CMake використовує його. Інакше за замовчуванням завантажується GoogleTest v1.15.2. Для збирання бібліотеки й демонстрації без тестів і завантаження GoogleTest передайте `-DBUILD_TESTING=OFF` під час конфігурації.

## Як повторити експеримент

1. Запустіть звичайну збірку, як показано вище. Має пройти **35 із 35** тестів.
2. Окремо зберіть версію з навмисним дефектом.

   ```powershell
   cmake -S . -B build-bug -DLAB7_INJECT_BUG=ON
   cmake --build build-bug --config Debug
   ctest --test-dir build-bug -C Debug --output-on-failure
   ```

   Має пройти **28 із 35** тестів. Ненульовий код завершення CTest тут очікуваний. П’ять тестів виявляють зміну стану після винятку, а два — пошкодження елементів поза блоком після успішної заміни.

3. Повторіть команди першого кроку для `build` із параметром `-DLAB7_INJECT_BUG=OFF`. Ще раз мають пройти **35 із 35** тестів.

Щоб побачити ключову відмінність, запустіть цей тест в обох каталогах збірки:

```powershell
ctest --test-dir build -C Debug -R BoundsFailurePreservesState --output-on-failure
ctest --test-dir build-bug -C Debug -R BoundsFailurePreservesState --output-on-failure
```

В обох збірках вставка блока 2 × 2 в позицію `(1, 1)` матриці 2 × 2 спричиняє `std::out_of_range`. У штатній збірці буфер залишається `{1, 2, 3, 4}`, у дефектній стає `{0, 0, 0, 0}`. Тому тест перевіряє і виняток, і стан матриці після нього.

## Контракт і межі

- Кожен розмір належить діапазону від 1 до 128. Індекси нумеруються з нуля. Елементи — скінченні значення `double`. Посилання від `data()` дає доступ лише для читання. Не слід зберігати ітератори чи вказівники на елементи буфера після операцій, які його замінюють або обмінюють.
- `replaceSubmatrix()` перевіряє блок і межі, готує копію буфера, а потім фіксує зміну через `std::vector::swap`, який не породжує винятку зі стандартним алокатором. Для матриці m × n копія потребує O(mn) часу й пам’яті. Примусова відмова виділення пам’яті не тестується. Незмінність стану за такої відмови випливає з порядку дій у коді.
- Числові алгоритми використовують частковий вибір головного елемента й абсолютний допуск, за замовчуванням `1e-12`. Допуск можна змінити викликом методу. Проміжні нескінченні або NaN-результати спричиняють `std::overflow_error`. Цей проєкт демонструє обробку винятків і не оцінює числову стійкість на погано обумовлених матрицях.
